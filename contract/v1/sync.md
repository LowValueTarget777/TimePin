# 已连接日历的同步协议

按日历建立副本。用当前账号的 `GET /api/v1/state` 发现可选日历，设备自行选择要保存哪些日历。已选的日历即使从目录消失，也要处理其原有游标。实例只在请求到达时检查变更与授权。前台进入、手动刷新和系统允许的后台任务均可触发拉取。

## 初始同步与续传

向 `POST /api/v1/sync/pull` 发送 JSON。认证使用会话 Cookie 或范围包含目标日历的 Bearer 令牌。单本和全部日历令牌都逐本同步并重新检查成员权限。免登录分享仅提供公开窗口视图。

```json
{"calendarId":"work","limit":128}
```

第一份回包含 `status: "ok"`、日历元数据 `calendar`、数组 `changes`、不透明字符串 `cursor` 和布尔值 `more`。保存后把返回的游标原样放入下一次请求。CLI 可用 `timepinctl -f pull.json sync.pull` 发送相同请求。结构定义见 [OpenAPI](./openapi.json)。

- 新建副本从空库开始，接收全部现存事件，包括原始重复规则和单次例外。服务端不展开月份，也会略过建副本前就已删除的事件。
- `changes` 按本日历的变更位置升序排列。新增、修订和撤销恢复返回完整 `record`。删除只包含 `id`、`version`、`deleted: true`。同一事件在两次拉取之间多次编辑会合并为最新状态。
- `limit` 默认 128，范围 1～512。服务端也按约 1 MiB 的记录正文分页，单条记录保持完整。只要 `more` 为真便继续当前轮。分页过程中再修改的行会移到更高位置，已经传出的事件被删除也会补发删除标记。处理到 `more: false` 时，副本与该次读取事务的状态一致。
- 事件、删除标记、日历元数据和游标在设备的同一事务提交。按事件版本应用，同一版本可重放。一台设备对同一本日历串行同步。请求、响应或事务中断后沿用上次已提交的游标。中间发生新写入时，重试可能直接收到更新版本。
- 无变化时 `changes` 为空；名称、颜色、归属、可见性或有效角色改变才再次返回 `calendar`。其他日历的写入不会改变本日历的游标。游标签名绑定实例密钥、账号、令牌授权范围和日历，服务端每页都重新计算有效授权。

## 写入、冲突与撤权

移动端拉取时可附加 `"sources":true`。响应的可选 `sources` 对象按事件编号给出导入来源基准，供本地预览判断某项是否在上次导入后被人改过。缺少映射时按 0 处理。旧客户端继续收到原来的响应格式。

### 发布本机日历

安卓使用当前会话的 `GET state` 发现账号可访问的日历。新出现的授权日历用空游标建立副本，后续使用各自游标。前台通过 `GET changes` 合并未变化的检查；Web 隐藏的日历未纳入该摘要的事件位置，手机仍按游标检查。本机有待发操作或发布快照时，即使摘要相同也尝试发送。退出账号取消调度，撤权与并发编辑仍使用下文的回执处理。手机新建账号日历时在一个本地事务保存日历及待发布快照，随后新增的事件进入原发件队列。登录后自动为未关联实例的本机日历（含系统来源）保存并重试首次上传快照。已绑定其他账号或已撤权的副本仍由其原归属隔离。

手机先冻结快照并持久保存操作号，再向 `POST /api/v1/manage` 提交 `calendar.publish`。目标沿用手机上的日历编号。手动创建的日历使用 `mobile-<UUID>`，从安卓系统日历导入的日历使用 `system-<UUID>`。每个现存事件携带 `id,version,sourceVersion,event`。登录账号成为该日历所有者与上传事件的创建者。整次发布上限为 100,000 项和 16 MiB 请求正文。服务端在同一事务建立日历、事件、同步索引及回执。重复事件编号导致整次回滚。不同操作占用同一日历编号得到 HTTP 409。限定某本日历的令牌不能发布新日历。

断线后按原操作号和完整快照重发。发布开始后的本机改动在单独的待提交队列中等候。回执确认后，以原日历编号建立游标并提交队列。桌面组件继续引用原编号。发布仅携带现存事件，旧的本机批次仍可从原设备预览、撤销，撤销产生的实际变更同步到实例。

### 已连接日历的编辑

设备把用户输入和待提交命令在本地同一事务保存。重连时先拉取并处理授权与副本状态，再通过已有的 `POST /api/v1/commands` 发送原命令。重试使用相同的 `operationId`、`baseVersion` 和内容；服务端校验当前权限后返回原回执。手动操作、CLI、AI、导入和批次撤销产生的事件变更共用同一索引。

| 回包 | 设备动作 |
|---|---|
| 命令 `code: "ok"` | 应用回执并移除对应待提交操作。较旧回执不得覆盖已经同步的新版本。 |
| 命令 `code: "conflict"` | 同时保存用户的提案和回包的 `current`。用户可接受现有安排，或核对时段后以新操作号和当前版本提交自己的选择。远端已删除时也能辨认删除状态。 |
| 命令 `code: "forbidden"` | 标记写入被拒，重新核对日历角色。仍有读取权限时可继续同步。 |
| 同步 HTTP 200，`{"status":"revoked"}` | 该身份凭原游标确认已失去整本日历的访问权。清理该日历的事件、元数据和游标，保留本人未提交的输入并标记撤权，停止自动提交。其他日历继续同步。恢复授权后可以重新选中并建立副本。 |
| HTTP 403 | 当前身份无权读取或写入目标。首次访问不披露该日历是否存在。已有该身份的本地共享副本时按撤权清理。 |
| HTTP 401 | 暂停该凭据的网络同步，重新认证，核对实例和账号后恢复。 |
| 同步 HTTP 409 | 授权仍有效，但游标无法继续。将原草稿转为待核对，从空副本重建，避免把旧历史上的操作自动提交到恢复后的实例。 |

服务端在每次请求的同一 SQLite 事务内核对直接授权、团组成员关系和令牌上限。失去编辑权但仍通过其他路径可读时，回包给出新的有效角色。离线设备在下次联机时收到撤权。

## 存储、升级与恢复

安卓以登录账号的成员 ID 和原实例标识查询本机待提交队列。`drafts.list` 按操作顺序分页返回目录，`drafts.detail` 按编号及返回的偏移量分段读取本人保存的原始命令。两者离线可用。撤权后保留的命令可从「待提交与冲突」逐项保存为 UTF-8 JSON；保存不改变队列状态，重新获权也不会自动重放旧草稿。已收回的服务器日程和回执不会随草稿返回。可用日历、组件及助手选区继续按当前角色过滤。[安卓设备命令](./device.json)

安卓 Room v3 为存在本机编号碰撞的日历单独存储服务器编号，旧记录以原编号同步。登录后，以实例校验结果、成员 ID 和账号目录授权决定能否复用副本。退出时清空的副本从空游标恢复。无法核对的旧副本保留其待处理操作和系统来源；新副本使用独立游标接收当前账号的快照。设备设置和组件操作使用本机编号，实例命令、导入标识和服务器助手使用服务器编号。

库版本 3 为已有事件补上每本日历内的顺序号，创建 `event_sync(calendar_id,sync_seq)`。写事件与更新顺序号同事务，按游标从索引范围扫描；每个事件只占用一个当前位置，删除沿用事件表的版本标记。回执重放、只更新来源确认状态的导入不会推进游标。游标签名密钥保存在同一数据库，正常服务重启后仍可继续同步。

恢复旧备份或把副本切换为新的主实例时，先停服，在恢复的数据卷执行一次 `timepin -db /data/timepin.db -reset-sync` 再启动。设备会收到重建信号。正常升级保留原密钥。迁移与回退步骤见 [部署说明](../../README.md)。

标准库 Python [协议客户端](../../scripts/sync_client.py) 和 [验收脚本](../../scripts/verify_sync.py) 分别实现独立 SQLite 副本和真实 HTTP 断线、双设备竞争与字节计量，可供安卓阶段复用协议场景。

整本日历删除后，已登录的副本用原有效游标拉取会收到 `{"status":"revoked"}`。客户端沿撤权流程收回副本。旧日历编号再次发布返回 HTTP 409。
