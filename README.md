TimePin 由 LowValueTarget 开发，项目原创代码和文档采用 [MIT 许可证](./LICENSE)。随软件分发的库、节假日数据及构建工具有各自的[第三方许可声明](./THIRD_PARTY_NOTICES.md)。

[0.15.4 版本说明](./docs/releases/0.15.4.md) · [安卓安装与更新](./docs/android.md#安装与构建)

TimePin 是给家庭和小团队使用的自部署共享日历。一个 Go 进程提供中文 Web 界面和 HTTP API，数据保存在 SQLite 中。可以叠加多本日历、给事件选颜色、安排跨午夜夜班、修改重复日程中的某一次，或批量导入结构化班表。

安卓 App 可直接离线使用，桌面月历和近七天组件各自选择日历。登录服务器后，手机自动上传本机日历和已授权读取的系统日历，并接收账号可访问的日历与后续变化。安装、系统日历导入、日程提醒和模型配置见 [安卓使用与真机验收](./docs/android.md)。

## 日历服务器、Web 和安卓

访问实例首页会进入个人登录与注册页。登录后可在侧栏勾选日历，手机宽度下横向滑动顶部日历列表。点账号菜单中的「设置」，或点月份旁的设置按钮，可打开个人设置。「外观」管理主题、背景、选色和月历显示，「日历与协作」管理共享和邀请，「助手与导入」选择模型、预览和导入日程，「账号与访问」管理密码和接口令牌。桌面端点击侧栏账号上方的「日历助手」，右侧会打开对话面板。手机宽度下从月份工具栏打开。助手会逐段显示模型回复，点击面板外的空白处可收起并保留草稿。日历所有者和归属团组的管理员可从日历设置底部确认删除整本日历。[查看 Web 设置界面](./docs/web-settings.png)

后台入口为 `/admin`。部署者在宿主机初始化独立后台账号，此命令也可轮换密码，并撤销全部后台会话。在 Bash 终端执行以下命令，输入不会回显。单机模式把 `docker compose exec -T timepin /timepin` 替换为本机可执行文件，并使用实例实际的数据库路径。

```sh
read -rs -p '新的后台密码（至少 10 个字符）: ' console_password
printf '\n'
printf '%s' "$console_password" | docker compose exec -T timepin /timepin -db /data/timepin.db -set-admin admin
unset console_password
```

后台首页显示真实账号、日历、团组和授权计数。可发放一次性注册码与账号恢复码，维护团组成员、创建个人或团组日历并调整直接授权，关闭个人会话、只读链接、邀请或 API 令牌，并检查操作记录。实例设置包含注册策略、模型配置、存储状态和数据库备份。[后台界面预览](./docs/server-console.png)

数据库从版本 5 升级时保留个人账号、会话和日历，移除旧版账号的后台权限映射。由版本 5 或更早版本首次迁入独立后台时，执行上面的初始化命令。已有独立后台账号随数据库升级保留。用户登录和后台登录可以在同一浏览器并存，各自独立退出。

默认单容器同时分发个人 Web。如需独立托管，将 `internal/server/web/` 作为静态站点根目录，设置服务端环境变量 `TIMEPIN_API_ONLY=1`，用反向代理将个人站点同源的 `/api/v1/` 转发给服务器并保留 Host。后台继续从服务器的 `/admin` 访问；个人站点的反向代理可屏蔽 `/api/v1/admin/`。

Web 与安卓可以选择服务器模型或个人模型。个人接口支持 DeepSeek、通义千问、Ollama 和自定义兼容服务。浏览器直接连接所选服务，需要该服务允许当前网页来源跨域，并允许页面使用对应的 HTTP 或 HTTPS 协议。浏览器仅保存接入地址和模型名，密钥在当前标签页内存中使用。安卓个人配置由 Keystore 保护。后台设置的服务端密钥保存在受限 SQLite 数据卷中；切换服务地址时需提供新密钥。

默认 Linux NAS Compose 使用宿主网络，保留一个容器和数据卷。安卓在「设置 → 账号与同步 → 发现局域网服务器」查找同一广播域的 TimePin，再点地址登录。服务器监听 UDP 41873；HTTP 端口由 `TIMEPIN_PORT` 指定，可用 `TIMEPIN_LISTEN_HOST` 限定地址。要在反向代理或隔离网络内关闭发现，设 `TIMEPIN_DISCOVERY=0`，安卓仍可手动输入 HTTPS 地址。单机启动服务默认仅监听回环；对局域网提供发现时同时设置监听地址和发现开关。

## 在 NAS 或服务器启动

在项目根目录运行以下命令。首次从源码构建需要下载 Go 构建镜像及模块。运行时使用内嵌网页、时区数据和 SQLite 驱动。

```sh
docker compose up -d --build
```

打开 `http://服务器地址:8080`。首次启动时先在受信任的网络创建自己的账号，每个新账号都会得到一本个人日历。后续成员可以通过邀请链接注册。容器以 UID/GID 65532 运行，使用持久卷 `data`，默认上限为 1 核和 512 MiB。健康检查地址为 `/healthz`。

| Compose 环境变量 | 默认值 | 用途 |
|---|---|---|
| `TIMEPIN_PORT` | `8080` | 宿主监听端口；同机反向代理可设置 `TIMEPIN_LISTEN_HOST=127.0.0.1` |
| `TIMEPIN_CONSOLE_LAN` | 空 | 后台访问策略，填写 NAS 实际局域网地址及前缀长度，例如 `192.168.1.10/24`。管理页面与管理 API 要求局域网设备直连此地址。 |
| `TIMEPIN_TUNNEL_LISTEN` | 空 | 增加同进程回环监听，例如 `127.0.0.1:8080`，供 PassNAT 回源。须同时配置上述后台策略，并将主监听绑定到具体的局域网地址。 |
| `TIMEPIN_REGISTRATION` | `invite` | 首个账号直接注册，之后凭邀请注册；显式设为 `open` 可开放注册 |
| `TIMEPIN_SECURE_COOKIE` | `0` | 在 HTTPS 反向代理后设为 `1`，让会话 Cookie 只通过 HTTPS 发送 |

使用局域网或公网域名邀请成员时，从成员可以打开的地址登录并复制链接。对外提供服务时用 HTTPS，代理应保留原始 Host。

在家庭局域网部署时，设 `TIMEPIN_LISTEN_HOST=192.168.1.10`、`TIMEPIN_CONSOLE_LAN=192.168.1.10/24` 和 `TIMEPIN_TUNNEL_LISTEN=127.0.0.1:8080`（地址按实际替换）。将飞牛 PassNAT 的本地目标设为该回环地址和端口，手机使用隧道域名登录。个人 Web、手机同步和 APK 下载沿用成员权限。管理员从家庭网络打开 `http://192.168.1.10:8080/admin/`。所有公网代理都应指向回环入口，避免路由器将公网请求改写成局域网来源后转给管理入口。使用 HTTP 隧道时，手机到公网节点之间的账号密码和会话均为明文。

## 自动化和日历助手

从 `/api/v1/openapi.json` 可获取公开 HTTP 契约。JSON CLI 与 MCP 使用同一组日历命令，支持班表预览、按来源更新和按批次撤销。网页可给自动化签发单本或本人所有日历的限权令牌。

实例共用模型默认使用 DeepSeek 的 `deepseek-flash`，支持自定义兼容地址和模型名。部署者在后台设置模型连接和密钥，并逐人授权。普通日历操作和结构化导入不需要模型密钥。[CLI、MCP、DeepSeek 配置和调用示例](./docs/automation.md)

## 单机运行

安装 Go 1.25 或更高版本，在项目根目录运行。默认监听回环地址，首次运行自动建立 `data/timepin.db`。

```sh
go run ./cmd/timepin
```

访问 [本机日历](http://127.0.0.1:8080)。可用 `go build -o timepin ./cmd/timepin` 构建单个可执行文件，Windows 使用 `-o timepin.exe`。程序接受 `-listen` 和 `-db` 参数，例如 `./timepin -listen 127.0.0.1:8090 -db ./family/timepin.db`。

## 发布 Go 服务端与 CLI

正式构建使用 `go.mod` 的精确工具链版本和 Dockerfile 的多架构镜像摘要。单独交付 Linux 二进制时，执行 `python scripts/build_go_release.py --arch amd64 --out <产物目录>`，arm64 将参数改为 `--arch arm64`。运行环境需有 Go 和 `govulncheck`（可用 `--govulncheck` 指定路径）。每个架构的输出目录包含服务端、CLI、目标平台源码扫描结果及 `release.json`。清单记录两个二进制的 SHA-256、实际 Go 构建信息及扫描库版本。

## 共享一本日历

手机宽度下，日历开关横排显示在月份下方，月视图直接显示班次时间。点日期可看当天安排，点彩条可打开事件。底部「管理」可以展开团组和账号菜单。[手机深色月视图预览](./docs/mobile-month.png)

- **和家人共享现有日历。** 点日历旁的「···」，选择角色并创建一次性邀请。已有账号的成员也可以按账号名授权。每个人独立勾选要显示的日历。
- **让团队长期持有班表。** 在「我的团组」中建组，新建日历时将归属设为这个组。组管理员默认管理组日历，普通组员默认只读。可以为指定成员或整个组补充投稿或编辑权限。移交组管理权后，原日历编号、事件和分享关系继续有效。
- **发给只需要看的人。** 在指定日历开启免登录只读链接。可以随时关闭或换新，旧链接下次请求立即失效。已经显示或复制的内容仍由接收人持有。
- **月历显示。** 月份标题旁的设置可切换周起始日、周数、农历、节假日地区和字号。节假日默认跟随查看设备的地区。安卓在设置中提供相同选项。授予读取权限后，打开 App 会自动导入手机系统日历，也可按日历启用提醒。[安卓使用说明](./docs/android.md)
- **网页导入班表。** 选择「批量导入」，选目标日历，上传 JSON 或粘贴内容，核对逐行预览后提交。为同一来源的每班保留稳定的 `externalId`，再次导入时会区分新增、修订、跳过和冲突。网页和 API 共用事件契约。[班表 JSON 示例](./contract/v1/README.md#结构化导入与预览冲突)

## 备份、升级与恢复

1. 用 `docker compose stop timepin` 正常停止服务，然后从该项目备份**整个数据卷**。例如先创建新的空目录 `timepin-backup`，再运行 `docker compose cp timepin:/data/. ./timepin-backup`。单机模式停止进程后复制整个数据库目录。备份包含账号、会话、邀请与只读链接，应限制访问。
2. 升级时保留相同的 Compose 项目名和卷，运行 `docker compose up -d --build`。程序启动时按 `PRAGMA user_version` 事务迁移。遇到更新的未知库版本会报告错误并退出。
3. 恢复时使用独立空目录或新卷，放入同一份备份的全部文件。容器用户需可读写该目录及文件。可先在另一端口运行 `./timepin -listen 127.0.0.1:8090 -db ./timepin-backup/timepin.db`，登录、查询原日历并确认分享权限后再切换。需要回退时使用升级前的程序和对应备份。

4. 恢复备份接替原实例时，在首次开放访问前对恢复库运行 `./timepin -db ./timepin-backup/timepin.db -reset-sync`。容器部署可在恢复卷对应的 Compose 项目运行 `docker compose run --rm timepin -db /data/timepin.db -reset-sync`。客户端会重新建立共享副本并保留待核对的离线输入。正常升级直接保留游标。

### 后台数据库备份与恢复

在「服务器后台 → 实例设置 → 数据库备份」选择「创建备份」。TimePin 通过独立 SQLite 连接生成一致快照，校验完整性后才展示文件名、时间与大小。正式容器位于 `/data/backups/`。复制该文件到独立的存储位置，并保存同版本部署配置与模型环境变量。恢复时从快照复制到新目录并命名为 timepin.db，按上面的恢复流程验证并执行 `-reset-sync` 后再切换。后台备份列表记录生成历史；主机管理员负责文件的保留与异机复制。

## 安卓更新

在服务器后台的「版本管理」上传 TimePin APK 并填写更新说明。安装包包含同一次构建写入的版本描述，支持官方日常版、自签名社区版、预览版及 QA 包分别发布。制作新版本时更新 `contract/v1/release.json`，提高构建号，使用与旧安装包一致的签名并妥善保存签名密钥。自部署者可以直接分发作者发布的官方 APK，也可以使用自己的长期密钥构建独立包名的社区版。两条渠道的首次安装、服务器分发和升级步骤见[安卓构建与更新](./docs/android.md#自签名社区版)。成员可从个人 Web 的「设置 → 关于 TimePin」下载实例提供的日常版或社区版。安卓的「设置 → 关于 → 检查更新」连接当前账号的服务器。覆盖安装由系统确认；首次使用更新功能时系统可能要求允许 TimePin 安装应用。
